# 브랜치 작업 피드백 리뷰 (feedback-review)

브랜치 작업이 끝난 후, 이번 세션에서 사용자가 준 피드백/지적사항을 정리하고 향후 같은 실수를 방지할 수 있도록 규칙이나 skill로 추가할지 검토합니다.

## 검토 대상

$ARGUMENTS

## 수행 순서

### 1. 피드백 수집

이번 세션에서 사용자가 지적한 내용들을 찾습니다:
- "~하지 마", "~하지 말고", "왜 ~했어?"
- "~해줘", "~하는게 낫지 않아?"
- 코드 수정 요청 (특히 단순화, 삭제 요청)
- 명시적인 규칙 추가 요청

### 2. 피드백 분류

| 유형 | 설명 | 예시 |
|------|------|------|
| 코드 품질 | 복잡성, 중복, 미사용 코드 | "단순화해", "안쓰는 코드 지워" |
| 프로세스 | 작업 흐름, 승인 절차 | "커밋 전에 물어봐" |
| 네이밍 | 변수명, 함수명 | "이름이 적절하지 않아" |
| 설계 | 아키텍처, 패턴 | "이렇게 분리할 필요 없어" |

### 3. 방지책 검토

각 피드백에 대해:
1. **이미 규칙이 있는가?** — `{{RULES_FILE}}` 확인
2. **기존 skill로 방지 가능한가?** — 설치된 skill 목록 확인
3. **새 규칙/skill이 필요한가?**

### 4. 추가 제안

사용자에게 다음을 제안합니다:
- `{{RULES_FILE}}` 에 규칙 추가
- 새 skill 생성
- 기존 skill 수정

## 출력 형식

```markdown
## 피드백 리뷰 결과

### 이번 세션 피드백 요약

| # | 피드백 내용 | 유형 | 왜 발생했나 |
|---|-------------|------|-------------|
| 1 | "..." | 코드 품질 | ... |
| 2 | "..." | 프로세스 | ... |

---

### 방지책 분석

#### 이미 규칙이 있는 것
- (해당 규칙 인용)

#### 새로 추가가 필요한 것

| 피드백 | 제안 | 추가 위치 |
|--------|------|-----------|
| "..." | 규칙: ... | {{RULES_FILE}} > Code Quality Rules |
| "..." | skill: ... | 새 skill |

---

### 추가할 내용 (승인 필요)

**{{RULES_FILE}} 추가:**
(추가할 내용)

**새 skill 생성:** (필요시)
- 이름: ...
- 용도: ...
```

## 주의사항

- 모든 피드백이 규칙화할 필요는 없음 (일회성 vs 반복 가능성 판단)
- 너무 구체적인 규칙보다는 일반화된 원칙 선호
- 사용자 승인 없이 `{{RULES_FILE}}` 나 skill 수정 금지
- 승격 대상 피드백은 [[memory-update]] 로 메모리에 영속화하는 것과 연계
