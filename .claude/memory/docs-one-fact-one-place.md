**문서를 고치기 전에 그 사실이 몇 군데 적혀 있는지 먼저 센다.**

```bash
grep -rn "<고칠 사실의 핵심 단어>" README.md docs/ AGENTS.md
```

같은 사실이 여러 곳에 있으면 한쪽만 고치게 되고, 나머지는 **틀린 채로 남는다.**
`core/` → 어댑터 drift 는 CI 가 잡아주지만([[build-drift]]) **산문은 아무도 안 잡는다.**

**Why:** 2026-08-11 하루에 같은 실수를 세 번 했다.

1. 훅 발화 검증이 끝났는데 `overview.html` 만 DONE 으로 고치고 README 는 "진행 중"으로 하루를
   더 뒀다.
2. "훅 4개가 자동으로 돈다"가 Codex 사용자에게도 해당하는 것처럼 읽히는 문제 — Codex 검수가
   `overview.html`·`guide.md`·README 에서 **각각 따로 세 번** 지적했다. 한 번 고칠 때 나머지를
   같이 봤으면 한 번에 끝났다.
3. README 안에서만 훅 표가 두 번, 같은 이슈 링크가 세 번 나온다.

특히 2번이 비싸다. **같은 지적을 세 번 받는 동안 매번 "고쳤다"고 보고했다.**

**How to apply:**
- 사실 하나당 **정본 문서를 하나 정한다.** 나머지는 그 문서를 링크한다. 요약이 필요하면
  한 줄까지만 두고, 상세는 옮겨 적지 않는다.
  - 예: 훅 제약의 정본은 `docs/codex-hooks.md`. README·`guide.md` 는 링크만.
- 고칠 때는 **고치기 전에 grep** 한다. 고친 뒤에 하면 이미 커밋한 뒤다.
- 리뷰에서 어떤 지적을 받으면 **같은 문제가 다른 문서에도 있는지** 그 자리에서 확인한다.
  같은 지적을 두 번 받으면 그건 문서가 아니라 **찾는 방식**이 잘못된 것이다.
- 표·목록은 특히 복제되기 쉽다. 두 문서에 같은 표가 생기면 하나는 링크로 바꾼다.
