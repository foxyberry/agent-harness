agent-harness

Claude Code + Codex를 위한 재사용 가능한 에이전트 하네스

"에이전트가 실수에서 배우는 시스템"을 특정 프로젝트에만 있던 것에서 → 어느 프로젝트에서나 /plugin install 한 번으로 쓸 수 있게 만든 도구. 핸드오프 · 자기개선 회고 · 커밋되어 공유되는 메모리 · 워크플로 스킬을 한 번에 배포한다.

왜 다른가 (차별점)

공개 하네스 대부분은 세션 종료 시 캡처까지만 한다. 이 하네스는:

  • 자기개선 훅 루프 — 편집 전 메모리 주입 → 편집 후 품질 경고 → 머지 시 회고 → 승격. 스킬보다 한 층 위의 자동 루프.
  • PR 머지 트리거 회고 — 세션 끝이 아니라 작업이 머지될 때 교훈을 남긴다.
  • 커밋되어 공유되는 메모리 — 로컬 transcript 대신 git에 커밋되는 메모리로 다른 머신·사람·툴이 이어받는다.
  • governance 내장 — _pending → 사람 승인 → committed. 잘못된 교훈·민감정보가 자동으로 박히지 않는다.

자동 훅 3개 (Claude 어댑터)

언제훅하는 일프로젝트 설정
파일 고치기 직전memory-search파일에 맞는 메모리를 컨텍스트에 주입routes.json
파일 고친 직후reflection코드 품질 경고 (정규식 규칙 + 내장 TODO/FIXME)reflection-rules.json
머지·세션시작·발화pr-merge-reflect미회고 PR 리마인더 + (opt-in) 자동 회고 초안env HARNESS_AUTO_REFLECT

핵심 설계 — 엔진과 재료를 분리

도넛 기계(엔진)와 반죽(재료)을 나눈 것에 비유할 수 있다. 기계는 만드는 법만 알고, 맛은 반죽이 정한다.

🛠 엔진 (core)

툴·프로젝트 무관 generic 부품. "무엇을" 주입·경고할지는 하드코딩하지 않는다. 모든 프로젝트가 공유.

🧾 데이터 (프로젝트)

.claude/memory/의 routes.json·reflection-rules.json이 "우리 프로젝트는 이렇게"를 정한다. 프로젝트마다 다름.

전에는 기계 안에 "Kotlin 규칙"이 통째로 굳어 있었다(하드코딩). 그걸 빼내 기계는 순수하게, 재료는 프로젝트가 넣도록 분리했다. Java든 Python이든 자기 재료만 넣으면 같은 기계가 돈다. 설정이 없으면 훅은 조용히 no-op.

⚠️ 자동 회고는 기본 꺼짐. 자동 회고 잡은 claude -p(AI)를 백그라운드로 띄운다. 설치만으로 몰래 AI가 돌지 않게 HARNESS_AUTO_REFLECT=1로 켜야 동작한다. 리마인더는 무관하게 항상 켜짐.

설치

Claude Code (플러그인 한 방):

/plugin marketplace add foxyberry/agent-harness
/plugin install agent-harness@foxyberry

Codex (skill-only — installer 구축 중):

codex plugin marketplace add foxyberry/agent-harness   # 배포 후
# 또는 로컬: codex plugin marketplace add ./

공통: 프로젝트에 project-template/ 복사 (AGENTS.md 정본 + .claude/memory/ 템플릿).

명령 (설치 후)

/handoff-save넘기기 전 이식 가능한 상태를 커밋 파일로 저장
/handoff-load이어받기 — 커밋된 핸드오프 1순위 + 현재 git 대조
/feedback-review받은 지적을 규칙/스킬로 승격 검토
/memory-update배운 것을 공유 메모리로 영속화 (_pending 검토·승격)

구조 (3층)

층위치내용
corecore/툴 무관 정본 — 스킬·훅·스크립트·메모리 스키마
adapterplugins/harness/, codex/core를 각 툴로 포장 (build.sh로 복사 생성)
opinion packproject-template/개인/팀 워크플로·회고 방식 (취향 — 선택 채택)

core가 정본이고 어댑터는 생성물. 수정은 core에서 → ./build.sh → 어댑터 재생성.

core/정본 — 훅 · 스킬 · 스크립트 · 메모리 스키마 (한 곳에서만 수정)
▼  ./build.sh 가 복사·렌더 (심링크 X — 크로스플랫폼 안전)
plugins/harness/Claude 어댑터 · hooks.json 자동발견
codex/Codex 어댑터 · skill-only (훅 defer)
▼  /plugin install · marketplace
사용자 프로젝트project-template/ 복사 → .claude/memory/ 데이터(엔진의 재료)

core 한 곳을 고치면 두 어댑터가 함께 생성된다. CI가 "core↔어댑터 동기화"를 강제 — build.sh 안 돌린 채 커밋하면 실패.
