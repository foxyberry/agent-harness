# 메모리 업데이트 (memory-update)

이 세션에서 배운 것과, reflect 잡이 과거 머지에서 미리 만들어 둔 대기 초안(`_pending`)을
함께 검토해 memory 로 영속화한다.

## Memory 업데이트 프로세스

### 1. 현재 MEMORY.md 읽기
auto-memory 디렉토리의 `MEMORY.md` 를 읽는다.
경로 = `~/.claude/projects/<프로젝트 절대경로에서 '/' → '-' 치환>/memory/MEMORY.md`
(시스템 메모리 지침에 현재 머신·프로젝트의 정확한 경로가 주어지면 그걸 사용)

### 1.5 대기 초안(_pending) 수집 — reflect 잡이 미리 만든 초안

`$CLAUDE_PROJECT_DIR/.claude/memory/_pending/` 아래 초안을 **재귀로** 모두 읽는다(하위 디렉토리 포함):
- `_pending/*.md` = 교훈 memory 초안 (type: feedback|project|user|reference)
- `_pending/decisions/*.md` = **의사결정 ADR 초안** (type: decision) → 승격은 아래 **1.6 절** 참조
reflect 잡이 **과거 여러 머지에서 미리 생성**해 둔 초안이다(현재 세션 것만이 아니라 누적분).

- 이 초안들 + 2단계의 현세션 추출 항목을 **하나의 후보 풀로 합쳐 함께 dedup** 한다.
- dedup: (a) 후보끼리 같은 주제면 하나로 병합(예: 거의 동일한 두 초안), (b) 기존 MEMORY.md/메모리 파일과 겹치면 새로 안 만들고 기존 파일 보강, (c) **`.claude/memory/_rejected.md` 에 이미 폐기한 것과 같은 얘기면 후보에서 뺀다.**
  - 단어가 달라도 같은 교훈이면 같은 것으로 친다. 사람이 이미 보고 안 남기기로 한 것이다.
  - ⚠️ **금지 목록이 아니다.** 그 사이 같은 일이 반복돼 값어치가 생겼으면 다시 올린다 — 대신 **무엇이 달라졌는지**(몇 번 더 반복됐는지, 어떤 비용이 났는지)를 후보 설명에 적어 사용자가 판단할 수 있게 한다.
- 승격 여부를 판정하기 전에 모든 후보에 **2.4절 수명 분류를 먼저 적용**한다. 작업 상태·재구성 가능한 값은 승격·병합하지 않고 폐기 후보로 제시한다.
- 각 후보 판정 = **승격 / 병합 / 폐기**. 사용자에게 간단히 제시하고 확정.
- 처리한 초안은 `_pending/`(및 `_pending/decisions/`) 에서 **삭제**(승격이든 폐기든). 미결정분만 남긴다.
- **폐기한 것은 `.claude/memory/_rejected.md` 에 한 줄씩 append 한다** (없으면 만든다). 파일을 지우면 거절했다는 사실이 사라져서, 다음 세션이 같은 트랜스크립트를 읽고 **같은 초안을 또 만든다**(이슈 #109).

  ```markdown
  # 폐기한 회고 초안

  `/memory-update` 에서 안 남기기로 한 후보들. 회고 잡과 이 스킬이 같은 걸 또 만들지 않도록
  참고한다. **금지 목록이 아니다** — 같은 일이 반복돼 값어치가 생기면 다시 올려도 된다.

  - `slug-name` — 왜 안 남겼는지 한 줄 (2026-08-18)
  ```

  - **추가 전용**이다. 지우거나 고치지 않는다(오래된 건 자동으로 상한 밖으로 밀린다).
  - 이유를 꼭 적는다. "사소해서" 와 "이미 AGENTS.md 에 있어서" 는 나중에 다시 볼 때 판단이 갈린다.
  - ⚠️ **커밋하지 않는다(기본 gitignore).** 안 남기기로 한 교훈 목록은 곧 **작업 습관·실수 이력**이라, 메모리 tier 규칙상 개인 tier 다. 공개 저장소면 그대로 전 세계에 공개된다.
    - 같은 프로젝트 안에서는 Claude 와 Codex 가 **같은 경로**를 읽으므로, 커밋하지 않아도 두 툴이 함께 쓴다. 넘어가지 않는 건 **다른 머신**뿐이다.
    - 이유 줄에 **사람에 대한 서술을 쓰지 않는다.** "왜 이 후보를 안 남겼나" 로 충분하다("사소함", "AGENTS.md 와 중복", "일반화 불확실").
    - 어떤 항목이 팀에 공유될 값어치가 있으면 — 예: "이건 메모리가 아니라 `AGENTS.md` 규칙으로 갈 것" — 그건 **정식 공유 메모리나 규칙 문서로** 올린다. 이 파일을 공유 통로로 쓰지 않는다.

### 1.4 과거 세션 끌어오기 — **사람이 고른 것만**

기본은 **이번 세션**이다. 그런데 회고할 작업이 다른 세션·다른 툴에 있는 경우가 흔하다 —
Codex 가 구현하고 Claude 가 리뷰만 했으면 Claude 로그에 사용자 발화가 거의 없다.

⚠️ **자동으로 끌어오지 않는다.** "최근 세션 전부"를 후보에 넣으면 무관한 작업의 피드백이
섞이고, 그건 잘못된 규칙으로 굳는다. 후보는 **사용자가 고른 것만** 들어간다.

사용자가 과거 작업까지 보길 원하거나, 이번 세션에 재료가 거의 없으면 목록을 보여주고 묻는다:

```
python3 scripts/handoff.py history --from both --since 7d --limit 10 --project-dir "<지금 작업 중인 사용자 프로젝트 절대경로>" 
```
> ⚠️ 위 명령의 `scripts/handoff.py` 는 **이 SKILL.md 가 있는 스킬 디렉토리 기준 상대경로**다. 그 스킬 폴더로 cd 해서 실행하되, 위 예시의 `--project-dir` 를 **지금 작업 중인 사용자 프로젝트의 실제 절대경로로 바꿔서** 넘겨라 — 스킬 폴더는 플러그인 캐시라 사용자 repo 밖일 수 있어, 이 인자 없이는 git 루트 탐지가 빗나가 핸드오프가 엉뚱한 위치에 저장된다.

- 이 프로젝트에 속한 Claude·Codex 세션만 나온다(worktree 포함). 기간·개수는 조절한다.
- 특정 주제를 찾을 땐 `--grep <키워드>` 를 붙인다.
- **지금 이 세션은 후보에서 뺀다** — 자기가 자기를 회고 재료로 쓰면 같은 얘기가 맴돈다.

사용자가 고른 경로를 압축해서 읽는다(원본은 수 MB, 압축본은 사용자 발화를 통째로 남긴다):

```
python3 scripts/compact_transcript.py <고른 세션 경로> --require-attributed-user
```

여러 개를 고르면 각각 돌리고, **어느 세션에서 나온 후보인지 표시**해서 제시한다.
압축기가 `회고 거부`를 알리면 그 세션은 후보 풀에 넣지 않는다. 출처 불명 user 턴을 메모리
승격 근거로 쓰지 않는다. 옛 로그에서 덜 얻더라도 기존 규칙이 사용자 피드백으로 둔갑하는 것보다 낫다.

### 1.6 결정(ADR) 초안 승격 — `_pending/decisions/`

`type: decision` 초안은 교훈과 다르게 처리한다(스키마 정본: `.claude/memory/decisions/README.md`).

1. **ADR 게이트 확인**: 본문에 `## Alternatives`(안 고른 대안)와 `## Consequence`(결과)가 **둘 다** 있어야 ADR 이다. 없으면 ADR 로 승격하지 말고 일반 memory 로 돌리거나 폐기.
2. **`proposed_*` 는 제안일 뿐 — 사람이 확정**: 초안의 `proposed_chain`·`proposed_supersedes`·`confidence` 를 사용자에게 제시하고 고르게 한다:
   - **체인(축)**: **"기존 체인 `<slug>` 계속 / 새 체인 `new:<name>` / 폐기"**. **모든 ADR 은 정확히 하나의 `chain` 을 가진다** — 독립 결정이면 새 체인 하나를 판다("체인 없음" 상태는 없다). (잘못된 계보가 최악의 실패 — 자동 확정 금지.)
   - **대체(supersedes)**: 이전 결정을 대체하면 그 `id` 를 `supersedes` 에, 대체 안 하면 `supersedes: []`. (체인 배정과 별개다.)
3. **확정 frontmatter 로 변환** 후 `$CLAUDE_PROJECT_DIR/.claude/memory/decisions/<name>.md` 에 저장:
   - **파일명 = `<name>.md`** (설명적 kebab slug, 초안의 name 유지·정리). `id` 는 **파일명과 별개**의 frontmatter 필드다 — 파일명은 사람이 읽는 이름, `id` 는 링크·supersedes 가 무는 안정적 키.
   - `id: adr-YYYYMMDD-NNN` **부여**(그 날짜의 다음 순번). 한 번 정하면 불변 — 링크 대상이다.
   - frontmatter 값은 **한 줄로** 쓴다(`keywords: [a, b]` 인라인). 인덱스 파서가 줄 단위로 읽는다.
   - `proposed_chain` → `chain`, `proposed_supersedes` → `supersedes`(**단방향만** — `superseded_by` 는 저장하지 말 것, 조회 시 계산), `status: active` 추가, `confidence`·`proposed_*` 제거.
   - `description`(한 줄 요약)을 반드시 둔다 — INDEX·검색 요약이 여기서 나온다. 초안에 있으면 유지, 없으면 `name`·Context 에서 한 줄 생성.
   - `keywords` 는 반드시 채운다(검색 성공이 여기 달림) — 부실하면 보강.
4. **대체 관계 처리(단방향)**: 이 ADR 이 기존 결정을 대체하면, **기존 파일을 수정하지 말고** 새 파일의 `supersedes` 에만 기존 id 를 적는다. 기존 결정의 `status` 는 조회 시점에 "이 id 를 supersedes 하는 게 있으면 superseded" 로 계산(파일 양방향 수정 회피 — 오래된 파일 편집·충돌 방지).
5. **INDEX 등록**: `.claude/memory/INDEX.md` 의 "결정 기록 (ADR)" 섹션에 `[<id>](decisions/<name>.md) — [chain: <chain>] <한 줄>` 한 줄 추가. **섹션이 없으면**(첫 ADR 이거나 구버전 INDEX) 파일 끝에 `## 결정 기록 (ADR)` 헤더를 새로 만들고 그 아래 추가한다.
6. 처리한 초안은 `_pending/decisions/` 에서 삭제. **공유 tier 라 커밋 필요**(브랜치+PR).

폐기한 초안은 `_rejected.md` 에 남으므로 회고 잡과 이 스킬이 참고한다(같은 걸 또 만들지 않게). 생성-시 dedup 은 여전히 name 중복만 막는다 — 내용이 같고 이름이 다른 초안은 검토 단계에서 걸러진다.

### 2. 후보 = (대기 초안) + (이 세션 추출). 아래 항목을 추출

**feedback (실수 지적 / 확인된 좋은 패턴)**
- 사용자가 "왜그래", "하지마", "틀렸어", "실수" 등으로 지적한 것
- 반복하면 안 될 행동
- 사용자가 "맞아", "좋아", "그렇게 해줘" 등으로 확인한 비자명한 패턴

**project (프로젝트 지식 변경)**
- 머지로 확정된 비자명한 동작·계약과 그 이유
- 중요 설계 결정 변경
- API 계약 중 코드만 봐서는 알기 어려운 제약·해석

**reference (새로 알게 된 외부 리소스)**
- 새 문서, 대시보드, 채널 등

### 2.4 수명 분류 — 저장하기 전에 무엇인지 판정

각 후보를 scope보다 먼저 아래 셋 중 하나로 분류한다:

| 분류 | 예시 | 처리 |
|------|------|------|
| **영속 지식** | 반복될 실수, 비자명한 패턴, 설계 결정의 Why, 안정적인 계약 | 2.5절에서 저장 tier 판정 |
| **전환용 작업 상태** | 재개 체크포인트, WIP, 진행 중 PR, 다음 액션 | memory에 저장하지 않음. **실제로** 세션·툴·머신·사람을 전환할 때만 `/handoff-save` 제안 |
| **재구성 가능한 값** | 줄 수, 테스트 수, 열린 PR 상태, 현재 브랜치·커밋 | 저장하지 않음. 필요하면 값을 얻는 명령이나 정본 위치를 안내 |

- handoff는 일반 상태 저장소가 아니다. 전환할 때 현재 작업을 인계하기 위한 커밋 파일이므로 자동 생성·자동 이동하지 않는다.
- PR/이슈 번호 자체는 근거와 안정적인 식별자로 저장할 수 있다. `PR #123 머지 대기`처럼 변하는 상태를 영속 지식으로 저장하지 않는다.
- API 구조나 지표도 코드·대시보드에서 바로 재구성할 수 있는 현재 값은 저장하지 않는다. 장기적으로 적용할 계약·해석·주의점만 저장한다.
- `_pending` 초안이나 기존 memory가 작업 상태·재구성 가능한 값이면 승격·병합하지 말고 폐기 후보로 제시한다.

### 2.4.1 민감정보 검사 — 승격 전에 반드시 수행

모든 후보와 `_pending` 초안에서 API 키·토큰·비밀번호·쿠키·개인 식별정보·비공개 URL 등
민감정보가 포함됐는지 확인한다.

- 민감정보 원문은 개인/공유 어느 tier에도 저장하지 않는다.
- 교훈 자체가 필요하면 비밀값을 완전히 제거하거나 일반화한 뒤 다시 검토한다.
- 안전하게 일반화할 수 없으면 폐기 후보로 제시한다.
- 처리한 `_pending` 원문은 승인 결과에 따라 삭제하고, 완료 보고나 PR 본문에도 비밀값을 옮기지 않는다.

### 2.5 scope 분류 (개인 vs 프로젝트) + 라우팅 — 어디에 저장할지

각 후보를 **type과 별개로 scope로 분류**해 저장 위치를 정한다:

| type | scope | 저장 tier |
|------|-------|-----------|
| user | 개인 | 개인 |
| reference / project | 프로젝트 | 공유 |
| **feedback** | **케이스별 판단** | 아래 |

**feedback scope 판단:**
- **개인 취향** (말투·선호·이 유저와 일하는 방식: "결론부터 짧게", "이 방식 싫어") → 개인
- **프로젝트 규칙** (코드베이스/팀이 지켜야 할 것: "main 직접 푸시 금지", "kotlin javaParameters 필수", "Spring DI 패턴") → 공유
- **애매하면** (개인 습관인지 팀 관행인지 불분명) → **사용자에게 질문**: "이거 개인 취향이에요, 프로젝트 규칙이에요?" → 개인 / 프로젝트 / 안함

**저장 위치 (scope별):**
- **개인** → `~/.claude/projects/<프로젝트 인코딩>/memory/<name>.md` + 그곳 `MEMORY.md` 인덱스 (per-machine, 커밋 무관 — step 1 의 읽기 경로와 동일해야 이후 세션에서 로드됨)
  > ⚠️ Codex 세션 주의: 위 개인 tier 경로는 **Claude auto-memory** 라 Claude 만 다음 세션에서 자동 로드한다. Codex 는 재로딩 메커니즘이 없으므로, Codex 에서도 필요할 항목이면 공유 tier(커밋 메모리 + INDEX.md)로 저장을 우선 검토하라.
- **공유(프로젝트)** → 둘 중 성격에 맞게:
  - "반드시 매번 지킬 하드 규칙" → **`AGENTS.md`** 해당 섹션에 추가
  - "참고 사실·패턴·설계 결정" → repo **`$CLAUDE_PROJECT_DIR/.claude/memory/<name>.md`** (frontmatter; [[memory-search]] 훅이 Edit/Write 시 노출)

⚠️ 공유 tier 저장분은 **커밋 필요**(브랜치+PR — main 직접 금지). 개인 tier는 ~/.claude라 커밋 무관. 완료 보고에 "공유분 = commit/PR 필요" 표시.

### 3. 저장 규칙

**중복 확인 필수**: 기존 파일이 있으면 새 파일 만들지 말고 기존 파일 업데이트

**저장할 것 vs 저장 안 할 것**
- ✅ 반복될 실수, 비자명한 패턴, 설계 결정의 Why
- ✅ 코드만 읽어서는 알기 어려운 안정적인 계약·해석·주의점
- ❌ 재개 체크포인트·WIP·진행 중 PR·다음 액션
- ❌ 줄 수·테스트 수·열린 PR 상태처럼 변하거나 재구성 가능한 현재 값
- ❌ 코드에서 읽으면 알 수 있는 것
- ❌ git log/blame으로 알 수 있는 것

### 4. 파일 작성 형식

```markdown
---
name: 메모리 이름
description: 한 줄 설명 — MEMORY.md 인덱스에 표시됨
type: feedback | project | reference | user
---

내용 (feedback/project는 **Why:** 와 **How to apply:** 포함)
```

### 5. 인덱스 업데이트 (tier별)

- **개인 tier**: `~/.claude/.../memory/MEMORY.md` 에 한 줄 추가/갱신:
  ```
  - [이름](./파일명.md) — 한 줄 설명
  ```
- **공유 tier**:
  - `.claude/memory/<name>.md` 추가 시 **`.claude/memory/INDEX.md` 에 한 줄 등록** — Claude 는 [[memory-search]] 훅으로, Codex 는 이 인덱스로 읽는다.
  - `AGENTS.md` 추가분은 해당 섹션에 자연스럽게 편입.

기존 파일 업데이트 시 설명 문구도 같이 갱신.
